# 数据、训练和验证协议

此协议是**预注册式研究方案**，不是已经完成的实验记录。所有阈值和规模标为规划值；得到真实数据、模型和 GPU 后先记录硬件/数据指纹，再执行，不能回填想象结果。

## 1. P0：数据能否支持结论

1. 用本目录 `audit_npz.py` 审计本仓 selfplay `.npz` 的字段、形状、dtype、MSB 位解包、有效目标覆盖与异常；记录每个文件 SHA-256、生成配置、原始模型 SHA、规则/komi/对称策略、样本生成时间。不要从空白或 dummy 数据建立棋力报告。
2. 用 `globalTargetsNC[:,41:47]` 六段重组 128 位棋局哈希，按**整局**稳定分 train/validation/test（建议 80/10/10）；检测同局跨文件、重复 `(game_hash, turn)`、side position。保留时间外测试集与不同规则/komi 子集，避免仅同分布记忆。哈希字段可用本仓 [`training.rs`](../../crates/kata_data/src/training.rs) 的精确位段定义核查。
3. 输入只允许 `binaryInputNCHWPacked` 解包和 `globalInputNC`，以及有明确生产来源的行动/变化特征。`globalTargetsNC` 的搜索结果、未来棋盘、终局值只用于**监督、筛选或分层报告**，不能作为状态输入。否则容易标签泄漏。
4. 合法手必须从**对应规则、劫历史、棋盘和执子方**重放得到；`policyTargetsNCMove` 的 0 可能只是未搜索/无访问，不能当非法标记。pass 始终占第 362 槽，但是否可用、终局处理仍按本仓规则验证。
5. D4 增强要同时变换输入、362 路 policy、候选坐标和变化序列，pass 不变；同一原局的所有对称副本留在同一 split。
6. `.npz` 的 `valueTargetsNCHW` 第 2/3 通道可作未来**占位**监督，不能直接当完整 `s_{t+8/32}` teacher latent。训练状态转移目标时须另有顺序轨迹和合法重放。

数据审计通过只说明输入准备正确。若真实数据缺失、合法重放无法完成、跨 split 泄漏、或目标覆盖不足，停止依赖这些数据的训练结论，并在 [推进记录](04-推进记录.md) 写明缺口。

## 2. P1：最小可证伪实验

规划样本：先以 **10 万训练局面 + 各 1 万个独立验证/测试局面**为实验预算，来自足够多的不同棋局；这不是统计充分性的承诺，实际按棋局相关性估计有效样本。`d∈{128,256,384}`，首选 256。每组固定训练步数、数据、增强、优化器、随机种子，并至少 3 个 seed 报均值及按棋局 bootstrap 区间。

本目录的 [`train_probe.py`](train_probe.py) 是可运行的**受限前哨实验**：用小 CNN 对 362 个槽的访问目标比较归一化状态/固定行动向量与等参数两层线性 policy 头；按棋局切分、默认 3 seed、验证集选 epoch、测试集只在选择后评一次。它不产生合法手集合、不接入 B11 主干、不做 D4 增强或棋局 bootstrap，也没有完整价值/目差/领地头。因此它的结果只能作为 P1 数据/损失探针，不能单独通过本节的完整 P1 或模型部署门。两份用户归档的受限实测见 [首份试验](05-真实数据试验.md)与[新包复验](06-八月归档复验.md)；固定着法头的微弱优势未稳定复现，完整实验仍需补齐下表对照和上述验证项。

| 组 | 目的 |
| --- | --- |
| B0：现有 B11 推理模型 | 下棋质量与资源基线；不重新命名或改动其认证身份 |
| B1：相同训练主干 + 常规 policy 辅助头 | 控制「多一个头、多一些参数」的收益 |
| C1：固定 362 着法向量的 Go-CLM 头 | 测试状态—行动相似度是否在同等预算下胜过 B1 |
| C1a：C1 去掉 hard negatives / 改变 d | 识别结果来自对比目标、负例设计还是维度 |
| F1：只作未来棋盘辅助监督 | **单独**测表征目标，不把其增益归因于 CLM |

最小 CLM 探针的局面内目标为

\[
p_{\rm clm}(a\mid s,L)=\operatorname{softmax}_{a\in L(s)}(z_s^\top z_a/\tau),
\quad
L_{\rm rank}(s)=-\sum_{a\in L(s)}p_{\rm search}(a\mid s)\log p_{\rm clm}(a\mid s,L).
\]

`p_search` 由有效的访问计数归一化，训练行权重与目标有效标记照本仓定义使用；未覆盖的候选不能凭 0 访问判作坏着。这个式子在固定着法行动向量时高度接近普通 policy 蒸馏，因此 **C1 必须超过 B1 才值得进一步做 CLM 变化编码**。若直接用论文的跨 batch 双向 InfoNCE，应为多正例/同坐标重复、对称等设计去假负例机制；不把相同坐标在别局的好着当负例。

监督总损失应保留原 policy、价值、目差、ownership 等主要目标：`L_total=L_original+λ_rank L_rank`。`λ_rank` 在验证集选择，在测试集锁定，不允许为了 CLM 指标而放弃原 NN 输出质量。冻结主干、只训将来丢弃的 CLM 头只能用于表征探针，不能声称产生了新的可部署围棋模型。

## 3. P2：扩展到完整变化

只有 P1 的 C1 超过等参数 B1，或发现单步着法头明确的失败原因且值得检验变化序列时，才投资完整变化。规划规模 **100 万–500 万局面**，不是现存数据量。训练对为 `(局面, 合法 4–8 手候选变化)`；候选来源必须记录：自对弈真实连续着法、搜索真实 PV 或额外合法重放生成的变化。现有 `.npz` 不直接提供 PV 序列；随机拼接未来棋盘和当前 policy 不成立。

难负例只在满足最低搜索访问数、充分 Q 差及稳定性门的**已搜索合法候选**中选；Q 的 win-loss/score 是压缩定标值，须按 [`fill_q_value_target`](../../crates/kata_data/src/training.rs) 的 `/32000`、`/60` 还原。需要按同局结果、局面阶段、规则/komi 分层，避免模型只学规则文本或强弱标签。对一个局面多个质量接近的候选用软标签或多正例，不强迫唯一正答案。

完整变化的行动编码器约 0.5–2M 参数预算，和同等参数/计算量的普通候选重排器比较。候选来自当前搜索时可能很少复用，所以分别记录行动编码缓存命中率、编码耗时和端到端耗时；不能引用 CLM 文本演示的 9×。

## 4. 离线指标与停机门

- **数据健康**：字段/shape/dtype、非有限值、哈希切分泄漏、重复行、有效 policy/未来目标比例、按局面阶段的覆盖。审计失败先修数据，不调模型。
- **排序质量**：teacher 访问分布 KL/交叉熵、top-1/top-5、top-K 候选召回、具有可靠 Q 的 held-out NDCG、所选候选的 Q 差；按开局/中盘/官子、劫、规则与 komi 分层。对同一棋局的行做 cluster bootstrap。
- **完整 NN 输出**：胜负概率的 Brier/对数损失、目差 MAE、ownership MAE、policy top-1 和非法着法率。CLM 的候选 softmax 不能直接当这些指标。
- **门槛**：C1 必须在锁定测试集上对等参数 B1 有**预先指定的主要指标改善，且按棋局 bootstrap 的 95% 区间不跨 0**，同时原输出不退化到超出预设容忍线。若无改善，固定着法 CLM 方向结项；不因单个子集偶然优势上线。
- **校准**：对候选选择用可靠标签检查 ECE/Brier 与拒选风险；不能把候选概率称作胜率。温度只能在验证集拟合，测试集单次报告。

选定主要指标和容忍线必须在看测试集之前写入每次实验的 manifest。若连续改变数据、模型和阈值后又沿用同一测试集，测试集已经变成调参集，需另留新局作盲测。

## 5. 从研究模型到引擎的资格

本轮不做以下接入。将来若 P1/P2 有可信收益，应依次完成：

1. 可训练的 TF3 兼容图或明确的蒸馏/导出链；记录新模型参数量、训练代码版本、数据/权重 SHA、特征版本、规则范围。新权重是**新模型身份**，不能沿用原认证 plan 或原模型哈希。
2. 对**同一新权重**建立 Python/训练图 FP32 金标，完成 Rust/C++ 后端整图对拍，覆盖 policy/value/misc/ownership 和输入历史/对称/规则/后处理；采用与本仓现有严格数值纪律相称的预注册门。不能用「新模型对旧模型数值一致」当门，因为目标本来不同。
3. 若有引擎代码更改，先做静态输出一致性、合法着法/pass/劫与回退路径检查，再做真实 Worker/GTP 和相同硬件的 ABBA 端到端吞吐。对比基线还需包括**把相同计算预算增加给现有搜索 visits**。
4. 棋力采用冻结开局、换色、等 visits 与等时间两套配对对局，按开局对做置信区间；同时查早期认输、规则/komi 与优势方偏差。几百局只能发现较大差异，不能把几十局或一点点胜率波动写成提升。例如普通二项近似下 400 局胜率 50% 的 95% 半宽约 4.9 个百分点；1% 级收益要远更多局，并应考虑成对相关性。
5. 任一数值门、性能门或棋力门未过，正式模型继续用现有认证版本；保留实验结果与失败原因，不绕过 fail-closed 身份。

## 6. 存储与训练资源预算

- 100 万原始无 metadata v7 行约 7.6 GB（未压缩）；500 万约 38 GB，另加训练索引、轨迹/PV 和增强缓存。
- 若缓存 100 万行的全部 `361×768` 主干 token，FP16 约 `1e6×361×768×2 = 554 GB`；只缓存每局面 top-16 token 仍约 24.6 GB。应按需流式编码、选择有限候选或缓存压缩的全局/局部表示，不能把整盘激活当小文件。
- 75M 量级主干 + 训练优化器/梯度/激活的实际显存取决于微批、重算和精度；本轮没有本机 GPU 测量，不能承诺 RTX 5070 Ti 上的训练 batch 或耗时。训练混合精度与最终推理 FP32 对拍是不同要求。
