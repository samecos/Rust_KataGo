# 八月自对弈数据：四头轻量模型与 M5 Pro 推理测速

日期：2026-09-27。**结论：在这台 M5 Pro 的 PyTorch MPS 上，轻量模型相对同数据训练的较大研究基线，纯前向快 1.28–1.59 倍，含输入解包和输出回传快 1.10–1.39 倍；其测试集 policy 质量略低。**这证明该两档研究网络在本机有可复现的速度差，不能推断 RTX 5070 Ti 上正式 RustGo 的加速，也不是 CLM/Jev 自身的提速证据。

## 1. 数据和预先固定的比较

源包是用户提供的 `2026-08-20npzs.tgz`，SHA-256 `b541cb0e499b03a9d4aaf180eab000f3855cede5281047d796ab6bf604a857dc`。数据准备器不改原包，扫描 36,252 个 NPZ 成员的元数据；精确排除[前次探针](06-八月归档复验.md)的 1,800 个文件，并比对旧文件 SHA、排除旧棋局哈希。随后流式读取剩余 34,452 个 NPZ，其中有 **1,418,024** 条可用完整 19×19 policy 行；按 128 位棋局哈希稳定分成 train/val/test **1,130,029 / 144,866 / 143,129** 行（16,667 / 2,124 / 2,097 局），没有同局跨 split。完整来源、筛选与标签门在[数据摘要](runs/2026-09-27-multitask-m5/data-summary.json)。压缩训练缓存位于被 Git 忽略的 `data/2026-09-27-multitask-full/`。

实际训练前以固定种子 `20260927`、仅依 split code 均匀抽取 **200,000 / 20,000 / 20,000** 行，两个模型使用完全相同的行与训练顺序。训练行中 value 有效监督 178,577 行、score/ownership 各 178,419 行；验证/测试的覆盖见[监督覆盖记录](runs/2026-09-27-multitask-m5/supervision-coverage.json)。输入只有 MSB 解包后的 `binaryInputNCHWPacked [22,19,19]` 和 `globalInputNC [19]`；`globalTargetsNC` 等目标列仅作标签、权重与分组，不进入 forward。KataGo [写盘代码](https://github.com/lightvector/KataGo/blob/352de42b663862251343d863cb6d6edb11c122cc/cpp/dataio/trainingwrite.cpp#L386-L418)中的 `nextPlayer` 是这行的待落子方，胜负/目差以其视角编码；[ownership 同理](https://github.com/lightvector/KataGo/blob/352de42b663862251343d863cb6d6edb11c122cc/cpp/dataio/trainingwrite.cpp#L691-L702)。value、score、ownership 仅在完成局及官方相应有效权重为正时参与损失；行权重也乘到各头。

两组均为相同四头：362 路 policy、胜/负/无结果、目差标量、361 路 ownership。主干是 19×19 常规残差卷积，`dense` 为宽 64、6 块、**463,002** 参数；新候选 `compact` 为宽 48、4 块、**181,562** 参数，参数减少 **60.8%**。网络层与前后处理接口相同，改变的只是宽度和块数。它们是独立 PyTorch 模型，**不能作为 TF3 权重载入现有 RustGo 后端**。

设备：MacBook Pro / Apple M5 Pro / 64 GB、macOS 27、Python 3.14.7、PyTorch 2.14.0、NumPy 2.5.3、MPS。两组共用 AdamW `lr=0.001`、batch 256、种子 29、各 5 epoch；总损失为 policy CE + `0.5×`value CE + `0.1×`目差 Huber（网络以 20 目为单位）+ `0.2×`ownership MSE。各头按自身有效权重归一；验证集总损失选 epoch，**测试集只在选择后各评一次**。两个模型均选第 5 轮。训练总耗时 469.5 秒，其中 dense 281.9 秒、compact 186.2 秒。[完整训练记录](runs/2026-09-27-multitask-m5/manifest.json)保留逐轮指标与 checkpoint SHA。训练记录中的 `train total_loss` 是每批归一损失的行数加权平均；验证/测试是每头全局加权后重组，二者不能当同口径相减。policy top-1 对访问数并列按最小着法索引破平。

## 2. 独立测试集输出质量

| 指标，20,000 条同一测试局面 | dense | compact | compact − dense |
| --- | ---: | ---: | ---: |
| policy 访问分布交叉熵，越低越好 | 3.13864 | 3.21454 | **+0.07590** nats |
| policy teacher top-1 一致率，越高越好 | 29.261% | 28.566% | **−0.695** 百分点 |
| value 交叉熵，越低越好 | 0.70207 | 0.70022 | −0.00185 |
| value Brier，越低越好 | 0.46740 | 0.46623 | −0.00117 |
| 目差 MAE，越低越好 | 6.348 | 6.332 | −0.016 目 |
| ownership MAE，越低越好 | 0.54042 | 0.53433 | −0.00609 |

轻量模型的 policy 蒸馏明显退化；其他三头差异很小，单种子与单次留出集不能说明棋力优劣。它没有合法手重放/过滤、完整 TF3 输出及自对弈胜率评估。因此这里只把它作为**速度与质量权衡的研究模型**，不作正式模型替换或棋力提升声明。

## 3. 同机推理速度

两份**训练后权重**加载到同一 MPS 设备，使用[便携真实输入包](runs/2026-09-27-multitask-m5/benchmark-inputs.npz)中的 32 个完整 19 路局面。这些输入来自已排除的旧探针样本，**不是本轮独立测试集行**；只用于同输入速度计时。每个 batch 分别预热 10 次，随后 5 轮 ABBA/BAAB，每轮每模型 2 个块、每块 30 次调用；**每次调用后同步 MPS**，表中为每模型 10 个块的每次 batch 墙钟中位数。设备驻留口径计四头纯前向；完整搬运口径计缓存的 packed 输入 CPU 解包、上传、四头前向、全部输出回 CPU，不含 NPZ 解压。原始计时块、平台与软件版本、输入和权重 SHA 在[速度 JSON](runs/2026-09-27-multitask-m5/mps-speed.json)；M5 Pro 和 64 GB 硬件规格记录在本节上方。

| batch | 口径 | dense ms/batch | compact ms/batch | compact 相对速度 |
| ---: | --- | ---: | ---: | ---: |
| 1 | 纯前向 | 0.815 | 0.639 | **1.276×** |
| 1 | 解包→输出回传 | 1.518 | 1.377 | **1.103×** |
| 8 | 纯前向 | 1.185 | 0.837 | **1.416×** |
| 8 | 解包→输出回传 | 1.951 | 1.600 | **1.219×** |
| 32 | 纯前向 | 2.415 | 1.523 | **1.585×** |
| 32 | 解包→输出回传 | 3.285 | 2.368 | **1.387×** |

全部六个口径均是正收益；每组原始块时间的变异系数约 1–3%，小于观测到的差距。batch 32 的纯前向约 **13,250 → 21,008 局面/秒**；含解包与回传约 **9,740 → 13,511 局面/秒**。这些数是该两档小型 PyTorch 网络的速度，**没有**乘上搜索请求、棋盘编码、合法手处理、CUDA 图或 Worker 排队。加速原因是较窄、较浅的卷积主干；它没有 CLM 变化序列编码或在线重排器。

## 4. 复现与交付文件

在项目根目录执行，Mac 的隔离环境用 `research/jev-clm-go/.venv/bin/python`；重建见 [README](README.md)。已存在的输出目录不可被数据准备器覆盖，复跑应使用新目录名。

```bash
research/jev-clm-go/.venv/bin/python research/jev-clm-go/prepare_model_data.py \
  --archive research/jev-clm-go/2026-08-20npzs.tgz \
  --exclude-manifest research/jev-clm-go/runs/2026-09-27-aug20/sample_manifest.json \
  --prior-sample-dir research/jev-clm-go/data/2026-08-20npzs \
  --out-dir research/jev-clm-go/data/repro-full \
  --split-seed multitask-v1-aug20-2026-09-27

research/jev-clm-go/.venv/bin/python research/jev-clm-go/train_student.py \
  --cache-dir research/jev-clm-go/data/repro-full \
  --out-dir research/jev-clm-go/runs/repro-m5 --device mps \
  --train-rows 200000 --val-rows 20000 --test-rows 20000 \
  --selection-seed 20260927 --seed 29 --epochs 5 --batch-size 256 --lr 0.001

research/jev-clm-go/.venv/bin/python research/jev-clm-go/benchmark_student.py \
  --dense-checkpoint research/jev-clm-go/runs/2026-09-27-multitask-m5/dense.pt \
  --compact-checkpoint research/jev-clm-go/runs/2026-09-27-multitask-m5/compact.pt \
  --input-pack research/jev-clm-go/runs/2026-09-27-multitask-m5/benchmark-inputs.npz \
  --output research/jev-clm-go/runs/repro-m5/mps-speed.json \
  --device mps --batches 1,8,32 --rounds 5 --iterations 30 --warmup 10
```
