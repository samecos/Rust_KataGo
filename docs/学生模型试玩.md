# CUDA 学生模型试玩

Worker 模式请使用新程序和独立的 batch 32 / capacity 64 配置，启动命令与实测见 [学生模型 Worker 调优](学生模型Worker调优.md)。下面的 GTP 启动方式继续用于本机 GUI 对弈。

这是供本机试玩的 `dense` 训练原型，尚未测定等级或 Elo。默认 19 路、中国规则、白贴 7.5 目；每手搜索上限为 **256 visits 或 2 秒**，关闭后台思考和自动认输。需要可用的 NVIDIA CUDA 环境。程序按模型文件内容识别格式，使用已有 `--model` 参数即可。

> 已完成：20 轮 CUDA 训练，按验证集选择第 19 轮权重。导出参数与 checkpoint 的 40 个 tensor 完全一致；固定 10 万条测试行评估和 5 次原生 CUDA/GTP 验收通过。模型 SHA-256：`fb3b77e796db158d3fb6a836291f7efa0fb33bc5b7ac0f0f5f9e45ae8061721a`。

本轮数据来自 KataGo 官方 **2026-09-28、2026-09-27、2026-09-26** 三份训练档案，合计 **12,154,787,867 字节**。已完成档案与缓存分片的首末 SHA 校验、19 路局面检查和完整行去重，保留 **16,233,907 个局面、270,575 局棋**。全量独立预检确认，按游戏哈希划分的训练、验证、测试集没有共同棋局。

本轮从随机初始化完成了单个 `dense` 网络的训练，固定抽取 **200 万／10 万／10 万行**用于训练／验证／测试，执行 **20 轮 CUDA FP16 训练，batch 256**，余弦学习率由 **0.001 降至 0.00001**。仅用验证集总损失选择最佳权重，随后评估固定测试集；棋力等级和 Elo 尚未测定。

本机文件：

| 用途 | 绝对路径 |
| --- | --- |
| 模型 | `D:\code\Rust_KataGo\models\student-playable-20261003\dense.rgmodel` |
| 新 CUDA 程序 | `D:\code\Rust_KataGo\target\student-playable-build-r1\release\katago-rs.exe` |

从任何工作目录启动 GTP：

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File "D:\code\Rust_KataGo\scripts\play_student_gtp.ps1"
```

这会启动标准输入/输出协议引擎；它本身不显示棋盘。需要查看 GUI 配置参数时，在上述命令末尾加 `-PrintCommand`，这一步不启动引擎。

在 Sabaki 添加引擎：打开 **File → Preferences → Engines → Add**，名称填 `RustGo CUDA student`，程序路径和参数分别填写以下两栏；Initial commands 留空。[官方引擎指南](https://github.com/SabakiHQ/Sabaki/blob/master/docs/guides/engines.md)、[官方设置界面](https://github.com/SabakiHQ/Sabaki/blob/master/src/components/drawers/PreferencesDrawer.js)。

程序路径：

```text
D:\code\Rust_KataGo\target\student-playable-build-r1\release\katago-rs.exe
```

参数：

```text
gtp --config "D:\code\Rust_KataGo\configs\gtp_student_play.cfg" --model "D:\code\Rust_KataGo\models\student-playable-20261003\dense.rgmodel"
```

新建棋局后，在 **File → Game Info** 设置棋盘 19×19、贴目 7.5、无让子。想自己执黑，就将黑方设为 **Manual**，白方用 **Attach Engine → RustGo CUDA student**；想执白则交换双方。若轮到引擎时没有自动落子，使用 **Engines → Generate Move**（F10）。双方都绑定引擎后可用 **Start Engine vs. Engine Game**（F5）自弈。[官方双方引擎设置](https://github.com/SabakiHQ/Sabaki/blob/master/src/components/drawers/InfoDrawer.js)、[官方菜单](https://github.com/SabakiHQ/Sabaki/blob/master/src/menu.js)。

引擎默认中国规则；载入其它规则的旧 SGF 时，先新建中国规则棋局再试玩。Lizzie 等标准 GTP GUI 使用相同的程序路径和参数。

用 **Play → Pass**（Ctrl+P）停一手，**Edit → Undo**（Ctrl+Z）悔棋。双方连续停一手结束后，GTP `final_score` 返回 `B+数字` 或 `W+数字`，数字已包含 7.5 贴目；新程序已修复中国规则终局固定分数问题。`printsgf` 保存的 `RE` 使用同一终局比分。

保存棋谱可用 **File → Save As**（Ctrl+Shift+S）选择 `.sgf`。也可在 GTP 控制台发送：

```text
printsgf D:\code\Rust_KataGo\target\student-playable-engine-r1\my-game.sgf
```

此 GTP 文件名应使用现有目录且不含空格。引擎保存的 SGF 可以重新载入继续查看。最终验收证据和测试棋谱已保存在 `target/student-playable-engine-r1`；协议、合法落子和 CUDA 对拍结果不构成棋力测量。

## 已完成的验证

| 指标 | 最终模型（CUDA FP32） | 固定基线 |
| --- | ---: | ---: |
| Policy teacher Top1 | 35.40424% | 0.85785% |
| Policy teacher Top5 | 66.77451% | 2.24202% |
| Policy CE | 2.73920 | 5.86653 |
| Value CE | 0.66805 | 0.69824 |
| Value Brier | 0.44021 | 0.46732 |
| Score MAE（目） | 5.80685 | 5.88538 |
| Ownership MAE | 0.51309 | 0.99867 |

基线只从训练集计算：策略位置频率、胜负概率和平均目差，ownership 固定为零。没有使用测试结果调整模型。这些结果衡量标签拟合，尚未测定对局等级或 Elo。

四头输出 batch 1/8 的原生 CUDA 与 CPU PyTorch FP32 对拍全部通过，最大绝对误差 `2.86102294921875e-05`。另完成编号 GTP、提子、非法落子拒绝、悔棋、SGF 回读和已知中国规则终局计分检查。两次有界自弈为：selfplay-short：64 手，capped_controller_passes，控制器追加 2 次停一手；selfplay-longer：160 手，capped_controller_passes，控制器追加 2 次停一手。到上限后追加停一手的棋局用于检查终局流程，不表示引擎自然下完一局。全部 5 次原生进程正常退出，无清理或重试。
