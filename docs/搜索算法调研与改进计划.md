# 搜索算法调研与改进计划

> 2026-08-25。目标:梳理本项目(kata_search)当前搜索算法,结合官方 KataGo 演进与最新学术成果,
> 解释并改善"下几步棋后新局面先选点集中、搜索一会儿才分散"的现象(下称"选点集中")。
> 结论先行:**算法本体已是 KataGo v1.11+ 形态(weight-PUCT + FPU + 图搜索 + 子树复用),但有
> 4 处官方功能在移植中断裂/未接线(wideRootNoise 随机项、pondering、subtreeValueBias 写侧、
> evalCache 默认关),它们恰好都指向该现象**。修复优先级见 §5。

---

## 1. 问题陈述

用户观察(分析模式,GUI 如 Lizzie):

- 在局面 P 长时间搜索后落子数手,到达后续局面 P' 时,引擎最初只给出**少数几个候选点**;
- 继续搜索一会儿后,候选点自然分散开——而此时总访问量并不大;
- 即 P 处的长搜索所积累的"分支意识",没有被有效传递到 P' 的呈现里(信息在换代时丢失)。

## 2. 本项目搜索算法现状(代码事实)

核心文件:`crates/kata_search/src/search.rs`(约 1.1 万行)、`node.rs`、`node_table.rs`、
`eval_cache.rs`、`subtree_bias.rs`;参数默认值在 `crates/kata_program/src/setup.rs`;
GTP/分析驱动在 `crates/katago/src/cmd/gtp.rs`。

### 2.1 选择公式(weight-based PUCT)

```
selection(child) = ±childUtility + exploreScaling * p(move) / (1 + childWeight)
exploreScaling   = cpuct(N) * sqrt(N + 0.01) * parentUtilityStdevFactor
cpuct(N)         = cpuctExploration + cpuctExplorationLog * ln((N + cpuctExplorationBase)/cpuctExplorationBase)
```

- 实现:`search.rs:5843-5895`;默认 `cpuctExploration=1.0`、`cpuctExplorationLog=0.45`、
  `cpuctExplorationBase=500`(`setup.rs:331-348`),与官方 C++ gtp_example.cfg 一致。
- 用 weight 而非 visits 访问数分母(`node.rs:186-192`),以支持 uncertainty weighting 与图搜索下
  edge/node 访问数分离。
- `parentUtilityStdevFactor = 1 + cpuctUtilityStdevScale*(parentStdev/prior − 1)`
  (`search.rs:6306-6327`,默认 prior=0.40/weight=2.0/scale=0.85):父节点效用方差大→探索更强。
  **这与 2025 年学术界的"方差感知 PUCT"方向同源(见 §4.3),KataGo 早已在父节点级落地。**

### 2.2 FPU(未访问子节点回退值)

`search.rs:6285-6373`:

- 基准 = `visitedPolicyMass^2 * parentUtility + (1−…) * nnUtility`(`fpuParentWeightByVisitedPolicy`,默认开);
- 折减 `reduction = fpuReductionMax * sqrt(visitedPolicyMass)`,根节点用 `rootFpuReductionMax=0.1`;
- 再按 `fpuLossProp` 向损失值方向混合。

**关键:visitedPolicyMass 越大(已访问子覆盖的 policy 质量越多),未访问子的 FPU 越悲观**
——这是"选点集中→缓慢分散"时间形态的第一主因(§3)。

### 2.3 图搜索(置换共享)

`useGraphSearch` 默认开(`setup.rs:468-473`);节点按 graph hash 入 `SearchNodeTable`
(65536 分片,`node_table.rs:17-56`);`thread.graph_path: HashSet<ptr>` 防环
(`search.rs:8188-8199`);`maybe_catch_up_edge_visits` + `graphSearchCatchUpLeakProb` 处理
edge visits 追赶(`search.rs:8217-8255`)。语义对齐官方 v1.11.0 的 MCGS(edge visit counts +
幂等 Q 重算,`recompute_node_stats` 全量重算 `search.rs:7091-7329`)。

### 2.4 子树复用(换代继承)

`make_move_with_prevent`(`search.rs:679-787`):找到已落子的子节点后,
`SearchNode::clone_for_tree`(`node.rs:484-558`)将子树统计**原样继承(不衰减)**,
并从 node table 回收旧根侧孤儿。无 pondering(§2.6),树只在 analyze/genmove 命令期间增长。

### 2.5 报告层(候选点呈现)

- 分析数据取根的**已分配**子,零访问子用 FPU 值补位(`search.rs:2507-2821`、`8834-8863`);
- GTP 输出过滤 `child_visits > 0` 后截断到 GUI 的 `maxMoves`(`gtp.rs:2663-2665`);
- 每次下降最多给一个未访问着法分配新子(`search.rs:6727-6811`);
- LCB 选点(`lcbStdevs=5.0`、`minVisitPropForLCB=0.15`)与 playSelectionValue 再加权
  (`search.rs:8348-8474`),使呈现的访问分布比树内更陡。

## 3. "选点集中"现象的机制定位

按 §2 代码事实,换代到 P' 后的首帧集中由以下因素叠加(均为预期行为,但强度可调):

1. **继承子带着旧搜索的大 visit/weight 出生**(§2.4),而旧搜索在深层子树里只扩展了少数分支;
   输出层又只显示 `child_visits>0` 的已分配子(§2.5)→ 候选天然少。这是"洞见丢失"的直接体现:
   P 处探索过但不在落子路径上的兄弟分支整棵被回收,只余 nnCache 里的孤立估值。
2. **FPU 随 visitedPolicyMass 的平方根加深悲观**(§2.2):继承子覆盖的 policy 质量大,
   未访问子估值被压低,新子要等探索项 `cpuct(N)·√N·p` 压过折减后才被首访 → 分散被推迟。
3. **PUCT 探索项随 N 增长**,分散终究会发生(用户观察到"等一会就散开"),且因为继承 N 大,
   散开时新增访问量不需要很多——这解释了"这时候搜索量可能并不多"。
4. **无 pondering**(G2):步间没有后台搜索替新根扩展兄弟分支,集中期完全暴露在下一帧。
5. **wideRootNoise 随机项缺位**(G1):Analysis 本应默认 0.04 的随机发散探索没有生效。
6. 报告层 LCB/playSelectionValue 再把分布削陡(§2.5),呈现上进一步集中。

## 4. 外部调研:官方演进与最新学术成果

### 4.1 官方 KataGo 演进时间线(与我们直接相关)

- **v1.11.0(2023):图搜索代替树搜索**。lightvector 的《Monte-Carlo Graph Search from First
  Principles》(docs/GraphSearch.md)给出推导:PUCT 的访问分布是"正则化策略优化"(RPO)的解,
  图搜索下必须改用 **edge visit counts** 作为后验策略、Q 用子统计幂等重算,否则朴素 DAG 化会
  有系统性偏差。本项目已按此实现(§2.3)。
  该文档还讨论了两个可选增强:**陈旧 Q 的主动传播**(后台线程遍历 DAG 刷新非当次路径祖先)
  与"子访问数>边访问数时是否提前截断 playout"——均为官方标注的实验空间。
- **v1.16.4(2025):实验性 EvalCache**(`useEvalCache`/`evalCacheMinVisits=100`,默认关)。
  官方注释:"交互分析往深处走、发现盲点解后回退,早期局面也更容易解出同一手段"——**正是
  用户所说'早先局面无法拥有后面的洞见'的官方对策**。v1.17.1 曾修 bug:缓存 key 未含搜索参数
  导致跨参数复用出错——我们实现/开启时必须把搜索参数纳入 key(检查项,见 §5-P1)。
- **v1.18.x(2026):搜索本体无大改**,重点在 CUDA/ROCm 后端与 transformer 模型;当前官方
  gtp_example.cfg 搜索参数与本节 §2.1/2.2 所列一致(cpuct=1.0/0.45, FPU=0.2/0.1,
  policyOptimism=1.0/根 0.2,valueWeightExponent=0.25,useGraphSearch=true 等)。

### 4.2 根节点发散手段(官方实践)

- `analysisWideRootNoise=0.04`(仅分析):"强制 KataGo 分析更多样的着法,极值 1 时把访问摊到
  全盘每一点"。注意它只影响分析、不影响对局强度口径。
- `rootPolicyOptimism`(根 0.2):以乐观 policy 探索,与 G1 的随机项互补。

### 4.3 学术前沿(2020-2025)

- **RPO 视角**(Grill et al. 2020, *MCTS as Regularized Policy Optimization*):PUCT 访问分布
  ≈ `argmax_π Σπ(a)Q(a) − λ_N·DKL(P‖π)`。给出"为什么访问分布=改进后的策略"的理论,
  也是官方 GraphSearch.md 的推导基础。
- **方差感知 PUCT**(Weichart 2025, arXiv:2512.21648, *Variance-Aware Prior-Based Tree
  Policies*):用 Inverse-RPO 方法从 UCB-V 系统推导出带先验的方差感知树策略
  `PUCT-V: q_a + c1·π(a)·σ̂_a·√N/(1+n_a) + c2·π(a)·logN/(1+n_a)`,在多个基准上不逊/优于
  PUCT,Welford 在线方差更新仅加常数开销。**与 KataGo 现有 `cpuctUtilityStdev*`(父级、全局
  缩放)不同,PUCT-V 是子级 σ̂_a 加权**;本项目节点已维护 `utility_sq_avg`(§2.1),实现门槛低。
  注意其基准多为 RL 自对弈训练场景,对"固定模型+分析"的收益需 ABBA 实测。
- **Gumbel AlphaZero**(Danihelka et al. 2022):根节点 Gumbel-Top-k + Sequential Halving,
  保证**极少模拟次数**下的策略提升,专治低预算下的候选遗漏。对自对弈/低 visit 场景有意义;
  对高 visit 分析模式与现有 PUCT 语义冲突较大,列为远期可选。
- **MCGS 学术版**(Czech, Korus, Kersting 2020):边上存 Q、增量追赶等"性能 hack"变体;
  官方文档评估后选择幂等重算,本项目同官方。
- 其他:Epistemic MCTS(2024 修订)用认知不确定性加权探索,思想与 uncertainty weighting +
  cpuctUtilityStdev 重叠,暂不单列。

### 4.4 综合判断

- 用户痛点的主要杠杆**不在换公式,而在把官方已有而移植断裂的发散/记忆机制补全**(§2.6 G1-G4),
  这些恰好逐一对应 §3 的 1/4/5 号成因与"洞见丢失"本体。
- 学术新方向(方差感知 PUCT)与现有 `utility_sq_avg` 基础设施天然契合,适合做成 tactic 开关
  走 ABBA,风险可控。
